# device_template

Boilerplate for adding a new device to the rxn bench, not a real device itself. Copy this whole folder to `devices/<name>/` and follow the checklist.

- **`capability/`** - reference SiLA feature + widget. `capability/backend/` is the reference SiLA2 server package (`rxn_bench_template`), with `TODO`-marked stubs for the hardware `Protocol`, SiLA feature, mock, and server wiring. Start here: [capability/backend/README.md](capability/backend/README.md) has the full step-by-step checklist for renaming and wiring things up. `capability/frontend/` is the reference device plugin: a minimal hand-built widget (no `.ui` file) plus the standard connection layer. Wire decoding uses compiled protobuf stubs in `capability/frontend/src/rxn_bench_device_template_frontend/proto/`, generated from the device's manifest entry in `rxnbench/backend/scripts/gen_proto.py` (run `make gen-proto` from `rxnbench/backend`). Delete the frontend half if your device doesn't need a custom widget yet - unrecognized servers fall back to the generic `GenericDeviceWidget`.

There's no `driver/` here on purpose - this template's mock is a generic Protocol stub, not real vendor hardware, so there's nothing to split out yet. A real device usually does need one: see `devices/ph_sensor/` for the fullest worked example (a driver with two transports, hardware CAD, and a toolhead config) and [Supported-Devices.md](../../Supported-Devices.md) for how capability/driver packages register with each other.
