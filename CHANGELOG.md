# Changelog

All notable changes to Rxn Bench are recorded here. Packages are currently pre-release (`0.1.0`, unversioned), so entries are dated rather than tied to semver releases until the first cut.

Format: newest entry first, one bullet per change, prefixed with the area it touches (`gantry`, `ph`, `client`, `frontend`, `docs`, etc.).

## Unreleased

- gantry: backend now enforces the experiment lock on the wire — `AcquireExperimentLock` returns a secret token, and motion/toolhead/workspace commands take an optional `Token` parameter; while a script holds the lock, tokenless calls (e.g. the UI or a stray client) are rejected with `ExperimentLockError` instead of being silently queued behind the script's moves. Homing commands are always rejected while locked; Pause/Resume/Stop stay tokenless so the UI can always halt a run. `rxn_bench_client.Gantry` attaches its token automatically, so scripts are unchanged. Verified end-to-end against a live mock server (2026-07-02).
- gantry: fix workspace-YAML state split — `GetWorkspaceYaml` and `Subscribe_CurrentWorkspaceYaml` now read from the controller's workspace manager instead of a feature-level cache that only `LoadWorkspaceYaml` updated. Loading a workspace by name (`SetWorkspace`, the UI's "Load" button) and the workspace restored from disk at boot were previously invisible to the stream and to `bench.gantry.get_workspace_wells()` (2026-07-02).
- gantry: new `GetLabware` command serves all bundled plate-geometry YAML as one document — the single source of truth for plate dimensions. The frontend deck canvases and `rxn_bench_client.get_workspace_wells()` now fetch it instead of hardcoding grids; the frontend's hardcoded 24-well A1 offsets had drifted ~9 mm from the backend's labware YAML (canvas drew wells where the gantry would not go). Labware YAML gains explicit `width_mm`/`height_mm` footprint fields (2026-07-02).
- gantry: multi-toolhead support — two (or more) heads can be physically mounted at once, with **per-head** mount confirmations that survive activation switches: confirm each head once at setup (`ConfirmToolheadMounted` / `mount_toolhead`, both idempotent), then scripts alternate between them unattended (`set_toolhead` is a pure software switch). `move_to_well` now refuses a head that was never confirmed mounted (`ToolheadNotMountedError`) or whose geometry is unvalidated — "confirmed calibrated if you plan on using it" is enforced backend-side. Homing invalidation moved from switching to the physical-change events (confirming/clearing a mount, removing a head), and only on actual state changes, so a mid-script switch no longer flips the bench to "Not homed" or breaks `save_and_park`. `ToolheadInfo` streams a new `mounted_toolheads` field (proto field 13, wire-compatible) so both UI slots show their own head's mount readiness; each slot's Activate switches the active head, the matching slot shows the ACTIVE badge, and mount/remove/calibrate only enable on the active slot (previously slot 2 was cosmetic and both slots drove the same state). Verified end-to-end against a live mock server (2026-07-02).
- gantry: `MoonrakerClient` HTTP calls now carry (connect, read) timeouts — a wedged Moonraker previously hung the request forever *while holding the hardware lock*, deadlocking every subsequent RPC (2026-07-02).
- gantry: dead-code sweep — removed the unused `sensor_registry`/`get_toolhead_sensor` (zero callers; contradicted the one-server-per-device model), the never-consumed `feature_state_changed` signal (from `connections/base.py`, the spec format, and the generator), the phantom `last_calibrated` widget field, the speculative generic SiLA feature fragments (`LinearMotion`, `XYZStage`, …) that would have bound `GantryWidget` to third-party servers it cannot drive, and the frontend's phantom 384-well plate entry (2026-07-02).
- frontend: gantry workspace loader now goes through `GantryConnection` (new `apply_workspace_yaml`/`load_workspace_by_name` + `workspace_op_done` signal) instead of opening its own raw gRPC channels with protobuf bytes hand-encoded via helpers imported from `core/generic_device.py` — the last plugin→core-internals boundary violation (2026-07-02).
- frontend: connection layer observability — stream failures and command errors are now logged (`logging`, first failure per outage at WARNING); `disconnect()` actually closes the channel; `GantryWidget` surfaces `error_occurred` in the Live-tab action label instead of dropping it; the toolhead-list `QThread` can no longer be garbage-collected while running (2026-07-02).
- ph: frontend connection now uses generated protobuf stubs (`devices/ph_sensor/frontend/proto/ph_sensor_pb2.py`) — the temporary hand-rolled varint/LEN helpers are gone from pH *and* from `device_template` (which now ships its own generated stubs, so new devices copy the right pattern). Verified against a live mock pH server (2026-07-02).
- ph: real-hardware I2C path fixed and testable — new `i2c_bus.SMBusI2C` adapter bridges smbus2 to the raw byte-stream interface the EZO driver expects (passing `SMBus(1)` directly, as `server.py` did, would have crashed with `AttributeError` on first use), plus `mock_i2c.MockI2CBus`, an EZO-protocol emulator that runs the real driver stack end-to-end in tests (9 new tests) (2026-07-02).
- backend: `gen_proto.py` generalized and moved to `software/backend/scripts/` — one generator with a per-device manifest (`_DEVICES`) replaces the gantry-only script; `make gen-proto`/`make check-proto` now cover gantry, pH, and the device template. Adding a device's stubs = one manifest entry (2026-07-02).
- backend: gantry test suite extended to 133 tests (lock-token gating, workspace-YAML source of truth, labware serving, mounted-flag reset on toolhead switch) (2026-07-02).
- frontend: first frontend test suite (`software/frontend/tests/`, 15 tests, headless via `make test`) — generator output structure + per-device golden checks (pytest twin of `make check-connections`), `_format_error` base64/details decoding, and server-labware→canvas spec conversion (2026-07-02).
- repo: add GitHub Actions CI (`.github/workflows/ci.yml`) running both backend suites, the frontend suite, and both drift checks on push/PR — everything it runs already existed as make targets; they were previously manual-only (2026-07-02).
- docs: `CURRENT_STATE.md` refreshed — closed gaps removed (pH I2C wiring was listed as open even though `server.py` already had it half-wired; now actually fixed), new stable decisions recorded (lock token, labware single-sourcing, no raw channels in plugins, toolhead-switch mount reset) (2026-07-02).
- backend: add `install.sh` (shared uv workspace, for local dev) and `scripts/install_service.sh` (per-package standalone venv, plus the pH `rpi` extra on ARM) for the split gantry/pH backend, so each service can be deployed/updated as its own systemd service independently of the other (2026-07-01).
- docs: fix `device_template/README.md`'s onboarding checklist — step 5 referenced a `sila_client.py`/`_FEATURE_REGISTRY` file removed in the June frontend refactor; replaced with the actual auto-discovery mechanism (`devices.all_devices()`) and the previously-missing frontend widget/connection-generation steps. Also fixed stale `connections/specs/`-era paths in the gantry and pH `connection_spec.yaml` header comments (2026-07-01).
- repo: reorganize to a device-first layout — each device is now a self-contained `devices/<name>/{backend,frontend}` folder (gantry, ph_sensor, device_template) instead of being split across `software/backend/<name>` and `software/frontend/.../devices/<name>`. `software/backend/pyproject.toml`'s uv workspace members now point at `../../devices/<name>/backend`; the Makefile and `scripts/install_service.sh` paths were updated to match. `rxn_bench_ui/devices/__init__.py` now dynamically loads each `devices/<name>/frontend/` from the repo root (via `importlib.util.spec_from_file_location`) instead of scanning a local subfolder. Added `devices/device_template/frontend/` — the template previously only covered the backend half. No behavior change for the SiLA/gRPC machine-separation boundary or the generated/handwritten connection split (2026-07-01).
- docs: add a top-level `devices/<name>/README.md` overview for gantry, ph_sensor, and device_template (what the device is, backend vs. frontend halves, links to the detailed backend README). Fixed stale content in the existing backend READMEs left over from the device-first move: broken `../pyproject.toml`/`gantry/tests/`-style relative paths, and gantry's systemd note which said "needs updating for the two-server architecture" even though that's now done (2026-07-01).
- gantry: fix `motion_platform.proto` drift — `gen_proto.py`'s hand-maintained `_FOOTER` template was missing the `ExperimentLock`/`Pause`/`Resume`/`Stop`/`GetExperimentState`/`ExperimentActive` RPCs that the checked-in proto (and feature.py) already had. Regenerated via `make gen-proto`; `make check-proto` now passes. No functional change — the compiled `motion_platform_pb2.py` is byte-identical (2026-07-01).
- ph: add a real test suite (`devices/ph_sensor/backend/tests/`) — 30 tests covering `AtlasScientificEZO`'s I2C wire-protocol parsing (status codes, comma-separated responses) via a fake I2C bus double, `AtlasPHSensor`'s calibration dispatch/status parsing, `MockPHSensor`, and the `PHSensor` SiLA feature layer (driven with `asyncio.run()`, no new test dependency). `make test-ph` previously failed with "no tests ran" (2026-07-01).
- frontend: close all four gaps in the generic FDL-driven device widget (`core/generic_device.py`). Added `core/fdl_types.py`, which builds real, typed protobuf messages at parse time from the FDL via `google.protobuf.descriptor_pool`/`message_factory`, replacing the previous heuristic byte-guessing decoder (`_collect_values`/`_encode_param`) for all per-feature command/property traffic — grounded in `SiLAFramework.proto` and verified against real live server traffic (decoded `Position` byte-identical to the compiled `motion_platform_pb2` stub; called `PHSensor.Calibrate` end-to-end). This also fixes a real latent bug where `Integer` params were zigzag-encoded when the real wire type is plain `int64`. Added `_ParamInput` for typed command inputs (`QComboBox` for enums, `QSpinBox`/`QDoubleSpinBox` for ranged numerics, recursive sub-forms for Structure/List) with client-side validation before Run. Added `_ObservableCmdRunner`, implementing the initiate → poll `<Command>_Info` → fetch `<Command>_Result` wire pattern, verified against unitelabs-cdk's own built-in `ObservableCommandTest` feature running as a real server. No compiled stubs existed for any of this before, by design — the widget still works against genuinely unknown/third-party SiLA2 devices (2026-07-01).
